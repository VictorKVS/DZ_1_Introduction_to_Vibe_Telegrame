# FATHER — Cost Model Placeholders v0.1

**Status:** ACCEPTED / PLACEHOLDER BASELINE  
**Purpose:** заранее встроить полную структуру затрат в модели проектов, даже если фактические денежные значения пока неизвестны.

## Принцип

FATHER не должен считать стоимость проекта только по разработке. Любой проект, агент, сервис, архитектурное решение и изменение должны иметь полный экономический профиль.

На раннем этапе неизвестные статьи затрат **не удаляются из модели**. Они создаются как обязательные категории со значением `0` и статусом `NOT_ESTIMATED` / `PLACEHOLDER`, чтобы позднее их можно было заменить фактическими денежными значениями без изменения структуры данных.

`0` в placeholder-модели не означает, что расход реально отсутствует. Он означает: **стоимость пока не введена/не подтверждена**.

## Базовая единица стоимости

До подключения финансового профиля проекта используется условная денежная единица:

```yaml
currency_mode: PLACEHOLDER
currency_code: UNIT
unit_value: 0
status: NOT_ESTIMATED
```

После определения страны, юрисдикции, поставщиков, цен и договора значение переводится в реальную валюту проекта: RUB, EUR, USD или иную разрешённую валюту.

## Временная структура

Стоимость должна считаться не одним числом, а по жизненному циклу:

```text
Discovery
  ↓
Design
  ↓
Build
  ↓
Test / Security / Legal / Compliance
  ↓
Deploy
  ↓
Operate
  ↓
Support / Change
  ↓
Decommission
```

Для каждой статьи храним:

```yaml
cost_item_id:
category:
phase:
quantity: 0
unit: UNIT
unit_price: 0
planned_amount: 0
actual_amount: 0
currency: UNIT
status: NOT_ESTIMATED
source: null
assumption: null
valid_from: null
valid_to: null
confidence: 0
```

## План / факт

Для каждой статьи обязательны два контура:

`planned_amount` — оценка до выполнения;

`actual_amount` — подтверждённый факт после получения счёта, табеля, метрики облака или иного evidence.

Разница:

```text
variance = actual - planned
```

Причина отклонения фиксируется как отдельный `Variance Cause` и попадает в Organizational Memory.

## Цены внешних ресурсов

Будущая версия должна уметь загружать ценовые профили:

- облачные провайдеры;
- LLM/API провайдеры;
- аренда;
- лицензии;
- тарифы специалистов;
- налоги и обязательные начисления;
- комиссии;
- стоимость электричества/каналов связи при применимости;
- региональные коэффициенты;
- курсы валют.

Пока эти значения равны `0`, но тип, единица измерения и источник цены существуют заранее.

## Налоги

Налоги не зашиваются в ядро единой цифрой. Они зависят от:

- юридического лица;
- страны/региона;
- налогового режима;
- вида операции;
- статуса исполнителя;
- НДС/VAT и аналогов;
- фонда оплаты труда и обязательных начислений;
- трансграничных расчётов.

Поэтому они подключаются через `Jurisdiction Profile + Tax Profile` и проходят Legal/Compliance Gate.

## TCO

Целевая модель должна поддерживать полный TCO:

```text
TCO = Build Cost
    + Infrastructure Cost
    + Operation Cost
    + Support Cost
    + Security/Compliance Cost
    + Change Cost
    + Risk Cost
    + Decommission Cost
```

Неизвестные компоненты остаются в формуле как placeholder `0 / NOT_ESTIMATED`, а не исчезают.

## Сценарии

Поддерживаются как минимум три сценария:

- `LOW / optimistic`;
- `BASE / expected`;
- `HIGH / conservative`.

Позднее для существенных проектов добавляются P50/P80 и Monte Carlo при наличии достаточных исходных данных.

## Экономика риска

`Threat & Loss Matrix` использует те же статьи стоимости. Это предотвращает существование двух несовместимых финансовых моделей: проектной и риск-ориентированной.

Угроза может создавать:

- прямой ущерб;
- восстановление;
- простой;
- недополученную выручку/маржу;
- Cost of Delay;
- штрафы;
- стоимость расследования;
- отток клиентов;
- opportunity cost.

## Gate Rule

Экономический Gate не должен выдавать `PASS`, если существенная статья затрат отсутствует как сущность. Она может иметь значение `0`, но должна быть помечена как `NOT_ESTIMATED`, чтобы пользователь видел экономическую неопределённость.
