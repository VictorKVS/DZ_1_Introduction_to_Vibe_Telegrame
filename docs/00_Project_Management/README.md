# 00 — Project Management

> Навигационный блок управления проектом FATHER.

## Назначение

Раздел хранит правила ведения проекта, стандарты документации, рабочий план, публикацию инженерного портала и организационные соглашения, которые должны соблюдаться всеми людьми и агентами FATHER.

## Документы

- [WORK_PLAN.md](WORK_PLAN.md) — поэтапный рабочий план от legacy-аудита до первой полностью замкнутой производственной вертикали FATHER.
- [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md) — непрерывный журнал разработки: шаг, причина, альтернативы, решение, проверка, результат и lessons learned.
- [DOCUMENTATION_STANDARD.md](DOCUMENTATION_STANDARD.md) — стандарт иерархии README, навигации, метаданных и связности документов.
- [GITHUB_PAGES_PLAN.md](GITHUB_PAGES_PLAN.md) — план превращения Markdown-документации в GitHub Pages / инженерный портал.

## Обязательное правило разработки

Каждое существенное изменение архитектуры, требований, ИБ, оценки, состава агентов, технологии или производственного процесса фиксируется в `DEVELOPMENT_LOG.md`.

Запись должна отвечать минимум на вопросы:

1. Что изменили?
2. Почему?
3. Какие варианты рассматривались?
4. Что принято?
5. Как проверить правильность решения?
6. Что получилось после реализации?

Таким образом GitHub хранит не только текущее состояние FATHER, но и историю его инженерной эволюции.

Работа выполняется по `WORK_PLAN.md`, но порядок этапов может уточняться на основании новых данных. Любое существенное изменение плана также фиксируется в Development Log с причиной.
